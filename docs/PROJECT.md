# KeyVivi 项目计划书

**项目目标**: 简洁、美观、轻量、绿色的 Windows 按键可视化工具。  
**技术栈**: Go + Fyne v2 + Win32 键盘监听。  
**开始日期**: 2026-09-30  
**最后更新**: 2026-10-02 02:10（UTC+08:00，来自本机系统时间）  
**规格与验收依据**: [project_spec.md](<project_spec.md>)  
**架构设计**: [architecture.md](<architecture.md>)（弃用 Fyne，自绘叠加层）

## 迁移中（2026-10-02 起）

v0.5 已确认可用，但 v1.0 所需的**整窗半透明与淡入淡出在 Fyne 上无法实现**（Fyne 无整窗透明 API，而透明度只能靠 `WS_EX_LAYERED`，该样式会让 GLFW 的 OpenGL 画面全黑）。已决定移除 Fyne，按 [architecture.md](<architecture.md>) 自绘叠加层。

预期收益：exe 23.3 MB → 约 4 MB；不再写 AppData；渲染变为纯 Go 可单测。`internal/keyboard`、`internal/display`、`internal/platform` 的钩子/热键/完整性检测全部保留，只重写 UI 装配层。

迁移步骤见架构文档第 11 节，共 5 步，每步可编译可验证、可单独回退。

## 交接摘要（2026-10-02 收尾）

**运行方式**：双击 [`launch.bat`](<../launch.bat>)。它把 exe 复制到 `%LOCALAPPDATA%\KeyVivi`、`Unblock-File`、再 `start`。必须这样启动，原因见下方"环境约束"。

**用户确认可用**（用 `launch.bat` 启动后实测）：全局按键采集、修饰键与组合键、连按计数、FIFO 队列显示、字幕位置水平居中贴底、字幕高度观感合适、托盘。

**仍待实测**：
- 计时类指标：停留 1.5 秒、队列各项独立到期、连续使用 10 分钟无泄漏。
- 托盘退出后进程是否在 2 秒内结束。
- 在 100% / 150% 缩放下的表现。

**现场保留**：`tests/artifacts/` 下的截图与日志未清理（已被 Git 忽略），包括 `place.log`（几何日志）等。

## 环境约束（最容易踩的坑）

**完整性级别由可执行文件的位置决定，不看启动方式。** A/B/A/B 四次可复现：

| exe 位置 | 完整性级别 | 后果 |
|---|---|---|
| 代理工作区内（`dist\`） | `0x1000` Low | 全局钩子只收得到本进程窗口的按键（焦点在别处没反应）；systray 写不了临时图标文件，托盘初始化失败 |
| 工作区外（`%LOCALAPPDATA%` 等） | `0x2000` Medium | 钩子全局有效；托盘正常，stderr 无 systray 报错 |

同一工作区内换启动方式（直接运行、`cmd /c start`、批处理）**都无效**。程序启动横幅会显示 `（受限环境 0x1000，仅本窗口有效）`。

另：`go build` 每次产出新哈希，未签名的 exe 没有 SmartScreen 信誉，可能弹"Windows 已保护你的电脑"。点"更多信息→仍要运行"一次即可；`launch.bat` 已加 `Unblock-File`。

- 真实程序启动时托盘初始化返回 Access is denied；获准的限制外启动也未返回进程，已取消，无测试程序残留。队列实际渲染、托盘操作、快捷键效果、10 分钟稳定性和可靠退出尚未通过桌面验收。
- 2026-10-01 排查：git-bash 与后台作业本身可写 `%APPDATA%\fyne`（探针目录创建成功并已清理），但由本会话启动的 KeyVivi.exe 无法创建 `AppData\Roaming\fyne\keyvivi`。同一进程树内表现不一致，判定为本会话进程令牌限制，属预期沙箱行为，不是程序缺陷；不由我用改权限的方式绕过。
- 同期确认框架限制：Fyne v2.8.1 无存储重定向接口，必然写 `%APPDATA%\fyne`、`%LOCALAPPDATA%\fyne`，systray 另写 Temp 临时图标；系统内已残留 `missing-id-*` 目录。
- 2026-10-02 决策：采纳“接受框架写入并如实说明”。绿色口径收敛为免安装、免管理员、无自启动、无服务、无注册表、配置在 exe 同目录、删除文件夹即移除主程序；Fyne 写入路径记入 README 并提供手动清理方式。规格第 3.4 节已更新，M10-04 改用新口径并新增 M10-06 清理复验。
- 2026-10-02 修复一处真实缺陷：原实现用 `SetWindowPos(SWP_SHOWWINDOW)` 显示字幕，`ShowOverlay` 返回成功且内部状态为可见，但 `IsWindowVisible` 仍为 False——被 Fyne/GLFW 驱动立即隐藏。改为由 Fyne 的 `Show`/`Hide` 管理可见性，Win32 只负责样式与定位。
- 2026-10-02 修复定位缺陷：改用 `MonitorFromWindow` + `GetMonitorInfoW` 工作区并按 DPI 缩放底部间距；原 `SystemParametersInfoW` 在逐显示器 DPI 下坐标不一致。同时修正我自己引入的 `SWP_NOMOVE` 回归（该标志会让坐标被忽略），由集成测试捕获。
- 2026-10-02 真实窗口实测（受限会话内，`KEYVIVI_DEBUG=1`）：扩展样式 `0x80800b8`，含 NOACTIVATE、LAYERED、TOPMOST、TOOLWINDOW、TRANSPARENT；窗口样式无 CAPTION/THICKFRAME；空闲时 `IsWindowVisible=False`。定位改用显示器工作区后窗口随之移动。
- 2026-10-02 环境限制：本会话桌面**跨进程注入的按键收不到**（最小 GUI 探针同样 `hook callbacks=0`），而同进程注入可收到（集成测试通过）。因此按键驱动的字幕渲染无法在本会话可靠验证，判定为本会话桌面/钩子链状态问题，不作为产品缺陷。
- 新增 `KEYVIVI_DEBUG=1` 诊断：记录钩子安装/消息泵、回调计数与队列长度，只记数量不记按键内容。
- **2026-10-02 找到"什么都没"的根因**：`WS_EX_LAYERED` 导致 GLFW 的 OpenGL 画面不被合成——窗口 `IsWindowVisible=True`、每个 Win32 调用都成功，屏幕上却零像素。移除该样式后字幕立即绘制（截图确认）。集成测试新增"必须不含 WS_EX_LAYERED"的回归断言。此前多轮"已通过构建"并未覆盖实际绘制，这正是用户看到空屏的原因。
- 2026-10-02 可观测性补强：托盘失败不再静默——捕获标准日志检测 systray 错误，弹出"托盘不可用"窗口并提供 `Ctrl+Alt+Q` 与按钮两条退出路径；所有提示窗口都带"退出 KeyVivi"；启动时短暂显示"KeyVivi 已启动"，用 `KEYVIVI_READY_HINT`（秒，0 为关闭）控制时长。
- **2026-10-02 找到"按键不显示"的根因（启动上下文）**：同一二进制，由本会话 shell 直接启动时钩子装上却收不到任何事件（同进程注入亦为 0）；经中间进程启动（`cmd /c start`、`go run`）则回调计数 0→2→4→6→8 正常递增，屏幕自检显示"通过"。对照实验：集成测试（`go test` 子进程）始终通过，独立二进制直接启动始终为 0。结论：低级键盘钩子受启动上下文影响，本会话内键驱动的验证结果无效，必须在普通桌面双击启动验收。
- 新增 `KEYVIVI_SELFTEST=1`：装好钩子后注入一对 F24 并在屏幕提示自检结论与回调计数，用于在无终端的情况下区分"钩子失效"和"输入未到达"。
- 本轮确认**渲染链路已通**：用户反馈启动横幅显示且文字居中，说明窗口绘制、可见性切换、Fyne 调度全部正常。
- **2026-10-02 最终根因：完整性级别由可执行文件的位置决定。** 同一 exe，放在代理工作区内启动 = `0x1000`（Low），复制到工作区外启动 = `0x2000`（Medium），A/B/A/B 四次复现；在工作区内换启动方式（直接运行、`cmd /c start`、批处理）都无效。Low 级别下 Windows 不把更高完整性窗口的输入交给全局键盘钩子，于是只在 KeyVivi 自己窗口有焦点时才显示按键；同因导致 systray 写临时图标被拒、托盘缺失。实测 `0x2000` 下**托盘零报错、钩子全局有效**。
- 上一条推翻了更早的"启动上下文"猜测：`cmd /c start` 当初看似有效，是因为当时前台窗口恰好也在低完整性。真正变量是 exe 的位置。
- 解法落到 `launch.bat`：把 exe 复制到 `%LOCALAPPDATA%\KeyVivi` 再 `start`，实测得到 `0x2000`。用户"昨天正常"的解释：昨天窗口常驻且有焦点，测试时从未在别的程序里打字，所以焦点依赖没暴露。
- 按用户要求取消「运行环境受限」「托盘不可用」两个弹窗：状态改写进启动横幅，托盘失败仍静默注册 `Ctrl+Alt+Q` 兜底退出，只写日志。
- **2026-10-02 收尾修复：字幕贴在右下角的两个独立原因。** 其一，Fyne 的固定尺寸窗口会**收缩到内容最小尺寸**，空文本让窗口只剩 170×82，居中算式于是把这个缩略图摆到了右边——现在背景矩形显式声明 1100×64 最小尺寸，实测窗口变为 1459×141（物理像素，DPI 1.25）。其二，**Fyne 在 `Show()` 时保存坐标、`doShowAgain()` 每次恢复**，所以原来的 `SetWindowPos` 定位每次重新显示都被撤销——现在定位改走 `desktop.Window.RequestPosition`，`ConfigureOverlay` 只负责样式，新增 `OverlayPosition` 计算坐标、`DescribeOverlay` 输出几何日志。
- 实测几何（`0x2000`，DPI 120）：`work=0,0..1920,1020`、`rect=221,741 1459x141`、`position -> 230,779`，居中且贴底。**窗口高度比设计的 64 逻辑像素厚，需目视确认是否可接受。**
- v0.5 保持进行中。托盘操作、暂停快捷键、10 分钟稳定性与可靠退出仍需用户用 `launch.bat` 启动后逐项回报。

## 风险与约束

- Fyne 桌面构建涉及 CGO/C 编译器；开发依赖与用户运行依赖分别验证。
- channel 不等于 UI 线程调度；后台协程更新 UI 需使用框架调度机制。
- Win32 钩子需有效消息循环；回调不得阻塞正常键盘输入。

- 透明色不等于透明桌面窗口；实际穿透、焦点和绿色存储行为必须测试。
