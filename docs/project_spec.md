# KeyVivi 项目规格与开发计划

**开始日期**: 2026-09-30
**最后更新**: 2026-10-04（Asia/Shanghai）

本文统一维护产品需求、里程碑、当前进度和验证记录。第2–5节定义目标与验收，第6–7节记录实际状态；目标不代表已完成。实现方式见 [设计文档](architecture.md)，开发协作规则见 [AGENTS.md](../AGENTS.md)。

## 1. 项目目标与范围

构建简洁、美观、轻量、绿色的 Windows 按键可视化程序，用于录屏、演示和教学。

- 已确定选型：Go + Win32 分层窗口 + Go 位图自绘；键盘监听、热键、托盘与消息循环使用原生 Windows API。
- 第一版默认采用独立圆角键帽，组合键显示为一个完整元素，不再使用 `|` 分隔；包含 YAML 配置文件和设置窗口。可选风格切换留到 v2.0。
- 总体里程碑为 M1 核心可用（v0.5）、M2 正式发布（v1.0）、M3 增强版（v2.0）；每个里程碑只分两个子项，进度与验收共用编号。
- 基础配置与设置 UI 按用户要求提前纳入 v1.0 的 M2.1；鼠标可视化、多显示器智能跟随及可选风格属于 v2.0 扩展。
- 首轮平台验收目标为 Windows 10/11 x64，不承诺 Windows 7 兼容。

## 2. 输入行为

### 2.1 单键与组合输入

按输入事件的按下/释放状态判断组合，不用固定超时猜测用户意图。

- 修饰键按下时暂不单独显示；若未参与普通键组合，释放时显示修饰键名称。
- Ctrl 按住后按 C，只产生一次 `Ctrl+C` 输入，画面为一个完整的 Ctrl+C 键帽；不先单独显示 Ctrl，释放后不补显 Ctrl。
- 无论按住 Ctrl 多久再按 C，都属于 `Ctrl+C`。
- 修饰键保持按下时，连续按 C、V，分别显示 `Ctrl+C`、`Ctrl+V`；不能在第一次组合后清空仍按住的状态。
- 只按 Ctrl+Shift 后全部释放，显示一次 `Ctrl+Shift`；顺序固定为 Ctrl、Alt、Shift、Win。
- 左右 Ctrl、Shift、Alt、Win 都要识别。展示名称可以合并，内部按下状态必须分开追踪。
- 普通键显示物理键名而非输入法生成的最终文本；不以按键可视化代替字符转录。

### 2.2 连按与键名

同一完整输入在相邻按下事件间隔小于 500ms 时累计；次数超过 2 才显示计数，如 `A ×3`、`Ctrl+C ×3`。第一次显示一项，第二次保留两项（单键表现为两个 A 键帽）；第三次合并当前连按的两项，计数以小标记附在最后一个键帽内。保留第一项的身份和入场进度，不能残留额外的 A。间隔达到 500ms 或出现不同输入时重置。系统长按自动重复也计入次数。宽度导致换行时，展示计数在新行重新累计，不能跨行合并或改写上一行。

字母、数字、常用符号及特殊键均须有名称。特殊键包括 Space、Enter、Backspace、Tab、Esc、Delete、Insert、Home、End、PgUp、PgDn、方向键和 F1–F12。

## 3. 显示与控制

### 3.1 最终字幕窗口

- 默认显示区域位于主显示器工作区左下角，距左侧、底部各 24 逻辑像素；位置及偏移可按第3.5节配置。默认最多 420 逻辑像素宽、三组左侧对齐，随 DPI 缩放保持可读。追加输入不重新居中或移动已有键帽；工作区较窄时降低行宽。单个组合仍超宽才缩小字号或末尾省略；逻辑输入保持完整。
- 白色键名，默认字号 18 逻辑像素；独立深色半透明键帽，背景约为 `rgba(20,24,31,0.88)`，带 1px 细描边和 2px 底部阴影。圆角 6、内边距左右 8/上下 6、单键最小宽度 32 均为逻辑像素，宽度随键名和计数自适应。缩小留白，保持原字号和输入规则。
- 每次完整输入对应一个键帽，Ctrl+C、Ctrl+Shift+S 等组合键不拆分；元素间距 8 逻辑像素，行间距仍为 16。不绘制整行衬底或 `|` 分隔，空隙保持透明；Num+ 和字面量 + 保留完整键名。键帽仅用于可视化，不接收点击。
- 无边框、无标题栏、无任务栏项；置顶、不抢输入焦点、鼠标点击穿透。
- 默认淡入 100ms、完整停留 1500ms、淡出 300ms；新输入更新字幕并重新计时，旧动画不得隐藏新字幕。
- 开发调试可使用普通测试窗口和临时退出按钮，但 M1 验收必须具备正式悬浮窗口与托盘退出入口。

### 3.2 纵向分组队列

- 连续输入在当前组向右追加，组内无横向队列切换；输入停顿达到 700ms，或下一项使行宽超过上限时另起一组。700ms 仅用于显示分组，不参与组合键识别。
- 默认最多同时显示 3 组，含退场组；旧组在上、新组在下，超出时整组淘汰最旧组。默认每组最多 8 个元素，组合键占一个；长键名或较窄工作区按实测宽度提前换组，不丢弃当前行前缀。容量可按第3.5节调整。
- 当前组每次追加或更新计数时整体续期，早先键帽不独立到期。新键帽淡入 100ms 后获得完整 1500ms 停留；已可见连按更新从更新时重新获得 1500ms，期限不得缩短。最后一次新键帽入场后约 1900ms 整组完全隐藏；整组共用到期及 300ms 退场，更新当前组不延长其他组。
- 500ms 内同一完整输入，前两次分别追加，从第三次起只合并当前行、本轮连按的两项；不同输入或达到 500ms 时开始新的连按，不改写此前同名输入。
- Ctrl+C 是一个输入项和一个键帽；各输入项独立入场，同一行共同纵向移动和退场。组切换以 120ms 移动，追加不触发横向移动；新组从底部裁剪边界滑入，不向工作区外扩展窗口。暂停立即清空全部组和快照。
- M1 验证分组、顺序、容量、计时与合并；M2 完善入场、退场与纵向移动。此规则按用户反馈替代早期五项横向独立到期方案。

### 3.3 托盘与暂停

启动后进入托盘，不显示空白主窗口。托盘提供暂停/继续、设置、关于、退出。Ctrl+Alt+K 切换暂停/继续，快捷键本身不进入字幕。

暂停立即清除当前字幕及待显示输入。恢复时重置按键状态，不能补显暂停期间输入。快捷键注册失败必须提示，托盘控制仍可用。


### 3.4 绿色与隐私

无需安装或管理员权限，不设置自启动、不创建服务、不写注册表配置。不记录或上传按键内容，诊断仅包含生命周期、数量、错误及几何信息，不能输出键码、组合名称或字幕文本。

v1.0 仅为配置持久化写入实际运行 exe 同目录的 `keyvivi.yaml` 及保存时的同目录临时文件；不写按键记录、日志、字体缓存或临时托盘图标。系统字体只读加载。删除程序及配置文件即可移除；Windows 自身的系统记录不属于应用主动写入。新增配置后须重新验收存储行为。

开发启动脚本 `launch.bat` 会复制 exe 到 `%LOCALAPPDATA%\KeyVivi`；这项行为必须在 README 明示，卸载时退出程序并删除该副本。发布 exe 在普通目录直接运行时不需要该复制步骤。

退出时停止定时器、卸载钩子、注销热键、移除托盘并释放所有窗口与 GDI 资源。关闭启动程序的终端不保证结束 GUI 进程，因此必须始终有可靠退出入口。

暂停立即清空字幕及动画快照，恢复不补显暂停期间输入。不承诺自动识别密码框，也不能删除已录入视频的字幕。

### 3.5 YAML 配置与设置窗口

配置使用实际运行 exe 同目录的 `keyvivi.yaml`，不受当前工作目录影响；只保存设置，不保存按键。首次缺失时使用并尝试生成带中文注释的默认配置；目录不可写时仍能使用默认设置，并明确提示保存失败及配置路径。缺失字段使用默认值，格式错误、重复/未知字段、不支持的版本或非法数值须提示且安全回退，保留原文件，不自动覆盖损坏配置。

托盘增加“设置…”入口，以原生 Win32 窗口提供三个纵向小节；每个小节标题为分组名称，其下每行一个配置项，左侧名称与说明、右侧控件。顶部预览与底部保存/取消栏固定，滚动仅作用于配置内容，不得出现重影或重叠；YAML 按同样的三个分组组织：

| 区域 | 首版可配置内容 |
|---|---|
| 显示区域 | 九宫格位置、水平/垂直偏移（各 -10000–10000px）、最大行宽（160–1200px） |
| 外观与布局 | 字号（12–48px）、文字/背景颜色（`#RRGGBB`）、背景不透明度（0–100%，默认88%）、元素/行间距（各0–40px） |
| 行为与动画 | 最多组数（1–6）、每组元素数（2–20）、分组停顿（100–5000ms）、停留时间（200–10000ms）、动画开关、启动时暂停 |

显示区域提供左上、上中、右上、左中、居中、右中、左下、下中、右下九个预设，作用于整个分组区域，行内仍左对齐。偏移以逻辑像素计，正水平向右、正垂直向下；默认左下，水平偏移 +24、垂直偏移 -24，最大行宽 420。区域高度由字号、行间距和最多组数自动计算，不另设高度配置；定位使用可容纳全部组的稳定区域，空白部分透明，最新组固定在区域底部，避免可见组数变化时整体跳动。位置越界时约束到工作区内，DPI 或工作区变化时重新计算；首版仍使用主屏，多显示器选择与跟随归 M3.2。设置窗口用九宫格选择器和位置示意预览帮助调整。

设置窗口提供示例实时预览、保存、取消、恢复默认；默认值沿用第3.1、3.2节。预览仅使用草稿配置与示例，不写入真实按键队列。保存须先校验，再安全写入并在 UI 线程应用，成功后立即生效并关闭设置窗口；取消或关闭窗口丢弃草稿，恢复默认也须保存后才持久化。写入失败保留草稿、原文件及活动配置，支持重试；保存保留已有注释。Tab导航、回车保存、Esc取消；屏幕空间不足时滚动，DPI变化时重排并保留草稿。关闭动画时输入立即显示，完整停留后直接隐藏，组移动不插值。

手动修改 YAML 后重启加载；首版不要求文件监控。开发启动器副本的配置位于 `%LOCALAPPDATA%\KeyVivi`，更新 exe 不得覆盖该目录中的用户配置；正常便携运行仍使用实际 exe 同目录。配置中时间使用明确的毫秒字段，尺寸使用逻辑像素，颜色使用加引号的色值，保持文件与 UI 的默认值、单位和校验一致。

## 4. 运行与验证约束

- 普通构建支持 `CGO_ENABLED=0`，无 C 编译器要求；Windows 的 `go test -race` 需要启用 CGO/C 编译器。用户运行不要求安装开发工具，仍需目标机器实测。
- 输入监听不得阻塞原应用；连按使用采集时间，积压或批量处理不能改变输入判断。不同DPI下字号、尺寸与位置须一致缩放。
- 本代理环境曾实测工作区内 exe 为 Low（`0x1000`）、工作区外为 Medium（`0x2000`）。运行位置是本环境验收前置条件，开发时使用 `launch.bat`；不将环境输入不可达误判为钩子实现缺陷。
- 代理启动窗口的截图和像素回读可能受到桌面隔离影响。API 返回成功只能证明调用与几何，真实可见性、置顶、穿透、焦点必须人工验收。
- 快捷键占用、托盘失败与字体缺失必须有明确处理；托盘失败时保留退出热键，所有退出入口失效时不能继续隐藏后台运行。
- 依赖版本以 [go.mod](../go.mod) 和 [go.sum](../go.sum) 为准；不凭预计体积、内存或 CPU 判断“轻量”完成。

线程、消息循环、分层位图和资源清理的实现约束统一见 [设计文档](architecture.md)；构建与测试命令见 [README](../README.md#构建与测试)，提交要求见 [AGENTS.md](../AGENTS.md)。

## 5. 里程碑与验收

只设 M1、M2、M3 三个总体里程碑，每个下设两个子项。子项编号用于归并任务与证据，不再给每个操作场景单独设置里程碑。

同一子项中的所有必需场景均须通过；失败或未测试不得被其他场景的通过结果抵消。后续里程碑保留前一阶段能力，M2 动画计时明确按第 3.2 节升级，不沿用 M1 的瞬时移除口径。

验收记录包含构建版本、日期与时区、Windows 版本、完整性级别、缩放、步骤和实际结果。输入与计数使用自动化测试；外观、焦点、穿透、托盘及分发必须真实桌面验证。编译成功不能代替功能验收。

### M1 核心可用（v0.5）

目标是输入准确、显示可靠、可暂停且可退出。M1.1、M1.2 全部通过，才标记 M1 完成。

**M1.1 输入与显示**

当前：输入、分组与主屏定位已接通，自动回归通过；可见性、穿透、焦点与位置的正式桌面验收待完成。

在记事本和另一应用验证第 2 节的单键、键名、左右修饰键、组合与连按：包含 Ctrl 按住 2 秒后组合、保持 Ctrl 连续 C/V、只按 Ctrl+Shift 后释放、左右 Ctrl 同时按住后释放一侧、快速重复、500ms 边界和更换输入。结果必须完整、无漏显或残留组合，原应用正常收到输入、不吞键。

持续输入不同键、快速重复、停顿 699ms/700ms 和错开 1 秒的输入，验证组内追加、停顿或行满换组、旧上新下、最多 3 组和整组淘汰。持续追加时前缀不逐键消失；仅当前组续期，上一组不被新组延寿；组内前两次重复均可见，第三次合并且不能跨行改写历史。关闭启动提示、空闲停表后首键也能显示。窗口位于主屏工作区底部，无边框、标题栏和任务栏项；置顶、不抢焦点，点击到达后方应用。此阶段不要求最终淡入淡出。

**M1.2 控制与生命周期**

当前：托盘、暂停、退出兜底及资源清理已接通，API回归通过；菜单、Explorer重启、故障及退出场景的正式桌面验收待完成。

启动后托盘可见，菜单含暂停/继续、关于、退出，无空白主窗口或临时退出按钮。菜单与 Ctrl+Alt+K 状态一致，快捷键本身不显示；暂停立即清空显示与待处理输入，恢复不补显暂停期间或跨暂停按住的键。

模拟热键占用、托盘失败及 Explorer 重启：占用有明确提示，托盘仍可控制；托盘失败有退出兜底，所有控制入口失效时不遗留隐藏进程；Explorer 重启后恢复图标。连续使用10分钟后退出，并验证关闭启动终端后仍可托盘退出；退出后2秒内进程结束、图标消失，钩子、热键、定时器及窗口/GDI资源释放。初始化失败也清理已有资源，规定的格式、vet、竞态测试和构建检查通过。

完成证据为输入/FIFO回归、窗口与控制的桌面记录、故障场景和退出后的进程/资源检查。旧版反馈不替代当前自绘装配层验收。

### M2 正式发布（v1.0）

前置条件是 M1 全部通过。M2.1、M2.2 全部通过，才发布包含基础配置和设置 UI 的最小版本。

**M2.1 界面与配置**

当前：键帽、纵向分组、动画、字体/DPI及缓存已实现；YAML、左下默认位置与九宫格配置、三组设置UI已接入，自动回归和原生控件集成验证通过，正式桌面回归待完成。
