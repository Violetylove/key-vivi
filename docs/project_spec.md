本文定义目标行为和各里程碑的通过条件，不代表当前实现已通过验收。

## 1. 项目目标与范围

构建简洁、美观、轻量、绿色的 Windows 按键可视化程序，用于录屏、演示和教学。

- 当前选型：Go + Fyne v2；全局键盘监听使用 Win32 API。
- 第一版采用极简字幕风格；胶囊风格等后续作为可配置项。
- v0.1 验证输入与显示；v0.5 提供基本可用的桌面工具；v1.0 完成最小可用版本的视觉、隐私和绿色分发验收。
- 配置文件、鼠标可视化、多显示器智能跟随及风格选择属于 v2.0 扩展，不作为用户所选 C1 最小版本的完成条件。
- 首轮平台验收目标为 Windows 10/11 x64，不承诺 Windows 7 兼容。

## 2. 输入行为

### 2.1 单键与组合输入

按输入事件的按下/释放状态判断组合，不用固定超时猜测用户意图。

- 修饰键按下时暂不单独显示；若未参与普通键组合，释放时显示修饰键名称。
- Ctrl 按住后按 C，只显示 `Ctrl+C`，不先显示 `Ctrl`、不单独显示 `C`，释放后不补显 `Ctrl`。
- 无论按住 Ctrl 多久再按 C，都属于 `Ctrl+C`。
- 修饰键保持按下时，连续按 C、V，分别显示 `Ctrl+C`、`Ctrl+V`；不能在第一次组合后清空仍按住的状态。
- 只按 Ctrl+Shift 后全部释放，显示一次 `Ctrl+Shift`；顺序固定为 Ctrl、Alt、Shift、Win。
- 左右 Ctrl、Shift、Alt、Win 都要识别。展示名称可以合并，内部按下状态必须分开追踪。
- 普通键显示物理键名而非输入法生成的最终文本；不以按键可视化代替字符转录。

### 2.2 连按与键名

同一完整输入在相邻按下事件间隔小于 500ms 时累计为 `A ×3`、`Ctrl+C ×3`；间隔达到 500ms 或出现不同输入时重置。系统长按自动重复也计入次数。

字母、数字、常用符号及特殊键均须有名称。特殊键包括 Space、Enter、Backspace、Tab、Esc、Delete、Insert、Home、End、PgUp、PgDn、方向键和 F1–F12。

## 3. 显示与控制

### 3.1 最终字幕窗口

- 默认主显示器底部居中，距离底部 80px；随 DPI 缩放保持可读，不截断组合名称。
- 白色字幕，默认字号 18；半透明黑色背景仅作为可读性衬底，不采用键帽或胶囊流布局。
- 无边框、无标题栏、无任务栏项；置顶、不抢输入焦点、鼠标点击穿透。
- 默认淡入 100ms、完整停留 1500ms、淡出 300ms；新输入更新字幕并重新计时，旧动画不得隐藏新字幕。
- v0.1 可以使用普通测试窗口和临时退出按钮；这些不算最终视觉实现。

### 3.2 FIFO 显示队列（v0.5）

- 新输入追加到右侧，最旧输入在左侧；最多显示 5 项，超出时移除最旧项。
- 每项独立停留 1500ms，到期即移除，不串行等待播放；其他项不被重新计时。
- 500ms 内连续同一完整输入更新队尾计数并刷新该项期限；不同输入或达到 500ms 间隔时追加新项。
- Ctrl+C 是一个队列项，不拆分修饰键。暂停立即清空整个队列。
- v0.5 验证顺序、容量、计时与合并；v1.0 完善入场、退场与移动动画。

### 3.3 托盘与暂停

启动后进入托盘，不显示空白主窗口。托盘提供暂停/继续、关于、退出。Ctrl+Alt+K 切换暂停/继续，快捷键本身不进入字幕。

暂停立即清除当前字幕及待显示输入。恢复时重置按键状态，不能补显暂停期间输入。快捷键注册失败必须提示，托盘控制仍可用。

### 3.4 绿色与隐私

无需安装，应用不设置自启动、不创建服务、不将配置写入注册表。不记录或上传按键内容。程序退出时停止定时器、卸载钩子、移除托盘图标并结束进程。

**框架限制与已决结论（2026-10-01 实测，2026-10-02 决定）**：Fyne v2.8.1 没有存储位置覆盖接口，`app.NewWithID` 会固定写入 `%USERPROFILE%\AppData\Roaming\fyne\`（settings.json、preferences.json、应用存储）与 `%LOCALAPPDATA%\fyne\`（缓存）；systray 还会在 `%LOCALAPPDATA%\Temp` 写临时图标文件。系统内已实测残留 `AppData\Local\fyne\missing-id-*`。

**决定：接受框架写入并如实说明。** 由此“绿色”定义收敛为：免安装、免管理员权限、无自启动、无服务、无注册表配置、应用配置位于 exe 同目录、删除程序文件夹即移除主程序。Fyne 自身写入的用户目录不视为缺陷，但必须在使用说明中列出实际路径与手动清理方式，不得对外宣称“完全不写用户目录”。


关闭启动程序的终端不保证结束 GUI 进程，这本身不属于缺陷；用户必须始终有可靠退出入口。

暂停可避免后续敏感输入被展示，但不承诺自动识别密码框，也不能删除已经录入视频的字幕。

## 4. 实现与构建约束

- Fyne 桌面构建涉及 CGO 和 C 编译器，不是仅安装 Go 就必然能构建。构建依赖与用户运行依赖须分别说明。
- 键盘钩子回调只传递事件，保持非阻塞；安装钩子的线程必须具有有效消息循环。
- **启动上下文会影响低级钩子。** 实测同一二进制：由 DSH 会话的 shell 直接启动时钩子装上但收不到任何事件（同进程注入也收不到）；经中间进程启动（`cmd /c start`、`go run`）则正常收到，回调计数逐次递增。因此键驱动的验收必须在普通桌面启动（例如资源管理器双击）下进行，不能以代理会话内启动的结果判断。
- **根因是完整性级别，而级别由可执行文件的位置决定。** 实测同一文件：放在代理工作区内启动得到完整性级别 `0x1000`（Low），复制到工作区外启动得到 `0x2000`（Medium），A/B/A/B 四次可复现。工作区内的启动方式（直接运行、`cmd /c start`、批处理）都逃不掉。Windows 不会把更高完整性窗口的输入交给低完整性进程的全局键盘钩子，于是钩子只剩本进程窗口可见——**焦点在本程序窗口时按键有效，焦点在别处完全没有反应**；同一原因让 systray 无法写临时图标文件，托盘初始化失败并在 stderr 报 `Access is denied`。实测 `0x2000` 下托盘无任何报错、钩子全局有效。
- **因此运行位置属于验收前置条件**：必须在工作区之外运行（`launch.bat` 会把 exe 复制到 `%LOCALAPPDATA%\KeyVivi` 再启动）。程序启动横幅会显示状态；受限时写「（受限环境 0x1000，仅本窗口有效）」，不再弹窗打扰。
- `KEYVIVI_SELFTEST=1` 会安装钩子后注入一对 F24 并在屏幕提示回调计数，用于区分"钩子失效"与"输入未到达"；该项只在排查时启用。
- 输入状态处理独立于 UI。从后台协程更新 Fyne UI 时使用 `fyne.Do` 等框架调度机制；channel 不会自动将 UI 操作移到正确线程。
- 透明、无边框、置顶及点击穿透须桌面实测；透明画布颜色、`SetFixedSize` 不等于这些窗口特性。
- 窗口可见性必须交给 Fyne/GLFW 的 `Show`/`Hide` 管理。实测用 `SetWindowPos(SWP_SHOWWINDOW)` 显示 Fyne 窗口会立即被驱动隐藏；GLFW 的显示路径本身不激活窗口，可直接复用。
- **叠加窗口不得设置 `WS_EX_LAYERED`。** 分层窗口走重定向表面合成，而 GLFW 的 OpenGL 交换不会更新该表面：窗口 `IsWindowVisible` 为真、所有 Win32 调用返回成功，屏幕上却一个像素都不画。字幕自带背景色，不需要整窗 alpha。集成测试已加断言防止回归。
- 定位使用窗口所在显示器的 `GetMonitorInfoW` 工作区，并按窗口 DPI 缩放底部间距。`SystemParametersInfoW(SPI_GETWORKAREA)` 在 Fyne 的逐显示器 DPI 感知下返回的坐标空间不一致，会导致窗口偏心或越界。移动时不得同时传 `SWP_NOMOVE`，否则坐标被忽略（集成测试已覆盖该回归）。
- 依赖版本以 [go.mod](<../go.mod>) 和 [go.sum](<../go.sum>) 为准。当前构建约 24 MB，不沿用原 walk 方案的体积估算。

```bash
go test ./...
go build -ldflags="-s -w -H=windowsgui" -o dist/KeyVivi.exe ./cmd/keyvivi
```

## 5. 验收规则

每个里程碑均有独立门槛，后续里程碑必须保留前一阶段已通过的能力。

验收记录包含构建版本、测试日期和时区、Windows 版本、缩放比例、操作步骤、实际结果及“通过 / 失败 / 未测试”。编译成功只能证明构建通过，不能证明功能完成。

输入状态与计数使用自动化测试；窗口、焦点、穿透、托盘及绿色分发必须真实桌面测试。任一必需项失败或未测试，该里程碑不得标记完成。

### 5.1 v0.1：核心功能验证

**目标**：正确识别用户输入，可靠更新字幕。允许保留普通测试窗口，不要求最终外观。

| 编号 | 验收操作 | 通过标准 |
|------|----------|----------|
| M01-01 | 在记事本和另一应用输入字母、数字、符号、特殊键 | 非本程序获得焦点时仍能显示键名；原应用正常收到输入，无吞键 |
| M01-02 | 分别按下并释放左右 Ctrl、Shift、Alt、Win | 每次单独输入显示对应修饰键一次；不漏显；释放后无残留状态 |
| M01-03 | Ctrl+C；Ctrl 按住 2 秒再按 C；Ctrl+Shift+S | 分别只显示完整组合；不拆显、不提前显示修饰键，组合释放后不补显修饰键 |
| M01-04 | 按住 Ctrl 连续按 C、V；只按 Ctrl+Shift 再全部释放；左右 Ctrl 同时按住、释放一侧后按 C | 依次得到 Ctrl+C、Ctrl+V；只修饰键组合只显示一次；另一侧仍按住时组合有效；全部释放后 A 不带 Ctrl |
| M01-05 | 快速三次 A；等待至少 500ms 再按 A；改按 B；连续重复 Ctrl+C；新键在旧字幕即将隐藏时输入 | 计数和重置符合第 2.2 节；最后输入约 1500ms 后隐藏（允许 ±100ms）；旧定时器不提前隐藏新字幕；临时退出入口可结束进程 |

**完成证据**：输入状态回归测试通过，以上桌面用例有结果记录。当前修饰键问题未验收前，v0.1 不算完成。
